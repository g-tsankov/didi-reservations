## Intent

**Problem:** Both `app.ts` and `admin.ts` keep all state in `$(() => {})` jQuery DOM-ready closures. State variables (`events`, `filter`, `current`, `modal`) are plain closure vars with no clear ownership, and event handlers use `function(this: HTMLElement)` + `$(this)` — a pattern that is error-prone and harder to type-check.

**Approach:** Convert each file into a single TypeScript class. State variables become typed private fields, all helper functions become private methods, and `$(this)` delegate handlers are rewritten as arrow functions using `e.currentTarget`. No logic changes — only structural.

## Boundaries & Constraints

**Always:**
- Behavior is identical before and after the refactor; every existing function must preserve its logic exactly.
- All five `$(this)` delegate handlers (2 in `app.ts`, 3 in `admin.ts`) must be converted to arrow function form: `(e) => { const el = e.currentTarget as HTMLElement; ... }`.
- All globals (`I18n`, `Time`, `SITE_CONFIG`, `icon`, `bootstrap`) continue to be accessed as globals — no ES module imports introduced.
- `I18n.onChange(fn)` registration must be preserved and called in the constructor.
- TypeScript must compile without errors (`npx tsc --noEmit`).

**Never:**
- Do not change any API request paths, request shapes, or response handling logic.
- Do not touch `src/js/common.ts`, `src/js/config.ts`, `src/js/i18n.ts`, or `src/js/globals.d.ts`.
- Do not introduce ES modules (`import`/`export`).
- Do not change any HTML templates or Bootstrap markup generated by render functions.

## Design Notes

The outer `$(() => { new AppPage(); })` wrapper keeps the same DOM-ready guarantee the closure provided. The class constructor is the new "top of the closure" — it sets up state fields and calls all the same setup code. Methods are called with `this.` internally, but since all event handlers are already arrow functions (after the `$(this)` conversion), there is no `this` rebinding risk.

For the `$(this)` delegate handlers, the pattern is:
```typescript
// Before
$('#events').on('click', '.is-bookable', function(this: HTMLElement) {
  const id = $(this).data('id') as number;
});
// After
$('#events').on('click', '.is-bookable', (e) => {
  const el = e.currentTarget as HTMLElement;
  const id = $(el).data('id') as number;
});
```

The `admin.ts` filter handler also toggles `.active` on `$(this)` — replace with `$(e.currentTarget).siblings().removeClass('active'); $(e.currentTarget).addClass('active')` or use the existing siblings-based DOM query.
